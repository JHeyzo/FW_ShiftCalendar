# 风味日历 · FW_ShiftCalendar

蓝色、圆角和磨砂导航风格的 Flutter 本地排班日历。交互采用适合排班记录的一致设计，不声称与某款系统日历逐项完全一致。

## 已实现

- 统一选中日期；月末、闰年日期处理；标题选日期、独立回今天；跨午夜及回到前台刷新。
- 年／月／周／日程列表／时间线／概览；横滑翻月、月格折叠和拖动；再次点选查看当日、长按新建。
- 日程与待办的新建、编辑、删除、备注、日历归属、颜色、星标、全天和起止时间。
- 待办完成／重开、筛选和排序；按日／周／月／年重复，单次／此后／全部修改或删除。
- 编辑重复事项显示所点实例的日期；“仅此项／此后”精确落到所选日期。“全部”按该实例的改期量平移整个系列。每月重复遇短月钳到月末，闰日年度重复在平年钳到 2 月 28 日，不改变原有日期锚点。
- 搜索标题、备注和日历名称；日历创建、编辑、配色、可见性和删除。
- 跟随系统／浅色／深色主题、农历显示设置；窄窗口、横屏和系统字体缩放适配。
- 本地 JSON 持久化、原子批量写入和事务串行；写入失败提示，不将失败当作保存成功；损坏数据不静默清空。
- Android 本地通知提醒，以及系统日历手动导入／导出。
- 可编辑循环班次模板；内置早晚夜休、上二休二，批量预览并生成真实日程。

## 循环班次与手动调班

在“设置 → 循环班次模板”创建或编辑 1–31 天的循环。每步可设置名称、颜色、工作／休息、起止时刻和跨夜；首日从第 1 步开始。选择本地日历及最多 366 天的日期范围后，先预览，再确认生成。可保留冲突日程或跳过冲突班次，休息日可选择是否生成全天日程。

同一模板、同一日期使用稳定标识，重新应用会更新该排班并覆盖其手工修改；不删除或覆盖其他标识的日程。修改模板不会自动修改已生成的排班。生成后直接编辑日程即可手动调班。

## 系统日历同步的边界

“设置 → 系统日历导入／导出”提供 Android 手动复制／更新闭环，需要系统日历权限。可选择系统与本地日历、今天至 180 天后的范围，每次最多处理 500 个实例；超过上限会明确提示。

- 导入通过稳定实例标识更新已有导入项，不重复创建同一实例；再次导入会覆盖同一实例的本地修改，不删除旧项。
- 导出仅处理本地日程，不处理待办，也不回导 `system:` 导入项。已导出的相同条目会更新；系统备注中保留来源标记以便识别与恢复映射。
- 重复日程按范围展开为独立实例，不保留系统的复杂重复规则；修改重复规则、移动系列日期等可能需要自行清理旧导出实例。
- 这不是后台实时双向同步，不自动传播删除，也不解决两边同时修改的冲突。原生日历权限、厂商 Provider 行为与实际账户同步仍需真机验证；自动化测试使用模拟原生通道，不代表已在用户日历中实际读写。

## 提醒与本地数据

提醒需在设置中显式开启通知权限，并允许 Android 的“闹钟和提醒”精确闹钟权限。有权限时使用精确定时；未允许时明确提示并降级为可能延迟的非精确提醒。权限变化后刷新会重新安排。未来 30 天内最多安排最近 64 条，启动、数据变动和跨日时刷新；长期不打开应用可能缺少后续重复提醒。隐藏日历不关闭提醒。精确闹钟也不保证绕过所有厂商限制；提醒送达、点击启动和重启恢复仍需真机验证。

本地日程、待办、模板和设置没有账号云同步；清除应用数据或卸载会丢失本地记录。农历和节日信息来自 `lunar_plus`，不将其伪装成用户日程。重复待办采用界面中注明的有限日期窗口；搜索每个重复系列只显示一次。

当前“休／班”预置安排仅覆盖 2025、2026 年；其他年份仍可显示农历节日，但不代表已加载对应年份的官方调休安排。

## 开发与验证

使用满足 `pubspec.yaml` SDK 约束的 Flutter；本次工作环境为 Flutter 3.47.7 / Dart 3.13.5。Android 构建需要 JDK 17+ 和 SDK 36。

```sh
flutter pub get
flutter analyze
TZ=America/New_York flutter test
flutter build apk --debug
```

全套测试使用纽约时区以实际覆盖夏令时切换：断言当天确实为 23／25 小时，同时验证全天结束日期、日序号与定时重复的本地时刻。不设此时区时，该专用测试会明确跳过，其余测试照常运行。

正式包通过被 Git 忽略的 `android/key.properties` 加载 `storeFile`、`storePassword`、`keyAlias`、`keyPassword`，然后运行 `flutter build apk --release`。密钥路径可用绝对路径；构建后删除临时配置。不提供该文件时 release 不会回退到 debug 签名。不要提交 keystore、`key.properties` 或本地 SDK 路径。
